# 四柱 × 地盘

本次模型更新：预测不再只看用神宫的神、星、门，还看**排盘四柱的年支、月支、日支、时支（及日干、时干）对地盘干支**的合、冲、刑、害、克。

## 角色

| 柱 | 管什么 | 权重倍率 |
|---|---|---|
| 年 | 长者、领导、主考官 | 0.72 |
| 月 | 朋友、亲戚、同僚 | 0.88 |
| 日 | 自己、当事主体 | 1.20 |
| 时 | 事情顺逆、当下气机 | 1.32 |

日时刑冲克合对**当日成事**权重最大。年柱偏尊长、考官、上级是否肯点头；月柱偏亲友是否来帮或添乱。

实现：`src/engine/pillar-earth.ts` 的 `pillarEarthFlags(chart, palace)`。事项、人事、运势、本命都走 `ganzhiFlags()`（内部调用上面这个函数）。天气走同一组 0/1 特征。

## 21 维特征名

```
年支合地盘 年支冲地盘 年支刑地盘
月支合地盘 月支冲地盘 月支刑地盘
日支合地盘 日支冲地盘 日支刑地盘
时支合地盘 时支冲地盘 时支刑地盘
日时支合 日时支冲 日时支刑 日时支害 日时支克
日干合地盘 日干克地盘
时干合地盘 时干克地盘
```

接在原 31 维（神门星 + 遁吟空 + 年积日 sin/cos）后面，合计 **52 维**。见 `src/engine/unified.ts` 的 `SCORE_FEATURE_NAMES`。

## 事项 / 运势怎么用

加性分 \(S\) 里直接加上各旗的 `weight`，再 \(P=\sigma(S/22)\)。断语 `reading` 会补一句「四柱地盘」：哪一柱合了或冲了地盘、对应哪一类人。

十二类事项（求财、事业、学业等）共用这一层，事业与学业仍然是两套事项校准，没有合并。

## 天气怎么用

气候带 12 区已按 52 维重训（样本约 2020-01-01–2026，训练到 2024-12-31，检验从 2025 起）：

| 指标 | 旧 31 维 | 加四柱 | 差 |
|---|---:|---:|---:|
| 单日有雨检验 | 71.63% | 71.50% | −0.13pp |
| 旬雨势检验 | 80.28% | 81.11% | +0.83pp |
| 晴/阴/雨三分检验 | — | 65.36% | — |

单日有雨仍被年积日季节项主导，四柱对**旬里程度**更有用。北京、西安、哈尔滨旬检验有提升；武汉、拉萨单日略回落。

区县旧模型仍是前 31 维。推理时 `logitWithOptionalTail` 自动叠上气候带平均四柱层，不必重训 3143 套区县权重也能用上新因素。

本地重训气候带：

```bash
npm run train:weather
```

写出 `src/engine/weather-weights.json`。

## 接口侧能看到什么

- `POST /v1/events` / `event` / `scan`：每条事项的 `ganzhiFlags`、`factors`、`reading`
- `POST /v1/fortune`：年/月/日运切片里的四柱角色说明
- `POST /v1/weather`：气候带 52 维；区县 31 维 + 共享四柱层
- `POST /v1/consult/ask`：第三段白话吉凶仍按总分与门星神生成，与四柱加减后的 `level` 一致

字段表见 [API.md](API.md)。
